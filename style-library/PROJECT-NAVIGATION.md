# Project navigation and review contract

projects.json is an ignored local navigation index. Production STATUS/approval-state/brief/storyboard/review notes remain authoritative. Empty installs create projects.json from projects.example.json. Changing note hashes flags stale navigation; read and reconcile decisions before refreshing.

A project record includes id, title, subtitle, format (video/presentation/carousel), state (in_progress/review/approved/final), stage, summary, next_step, primary_artifact, source_notes and artifacts. Optional cover_path and reference_id point to real saved assets. Each source note has project-relative path, label and SHA-256. Artifacts have stable id, label, type (video/board/carousel/document), version and role (current/assembly/storyboard/baseline/final/history). Video/document has path; board/carousel has frames with path/title/notes; downloads have path/label. URLs and availability are derived by the server, not stored. See scripts/smoke.py for a complete synthetic example.

Use scripts/register.py project <studio-entry.json> after reading/updating source notes. New registration cannot claim final approval. Replacing a record with an existing saved decision requires explicit reconciliation, preserving its approval-state.json/history. Unknown files/absolute paths/unsupported types/symlink escapes are unavailable. /project-files/<id>/<numeric-slot> serves only the exact registered project's allowlist.

Before a final review, register a matching pending library entry or prepare reference_entry plus reference_poster_source in the project descriptor. reference_entry uses the library shape (title, subtitle, creator/creator_id, summary, tags, palette, traits, keep, avoid, moments, notes, version, collection, evidence and media_path for video; slides for carousel; project_id/asset_type project for slide assets). The poster must be an actual saved image in this project. It is copied into a new versioned library poster only when the user marks final. Keep entry/version/media and any linked technique source hash/windows synchronized. Do not approve your own production output.

Review controls affect only the current primary checkpoint. Approve spoken cut advances to storyboard; Approve storyboard advances to edit; Approve & mark final promotes exact media/library metadata; Reopen requests changes and retains accepted assets. Historical checkpoints have no approval control. Events include UUID/date/version/files/hashes. STATUS receives a current-decision block, review notes append, legacy active-edit fields update when present and index note fingerprints refresh. Final does not publish.

Writes use exact Origin/Host/header/JSON guards, revision checks and per-file atomic replacement with private transaction backups. An unfinished prepared transaction blocks further writes. Inspect its named style-library/runtime/review-actions/<UUID>/transaction.json, confirm the before-images and current files, then `python3 style-library/review_actions.py recover <UUID>`. Recovery refuses to overwrite later edits. Do not delete journals to bypass a failed save. They and all actual owner registries/decisions are excluded from the release export.

## Review experience and saved notes

The project header stays compact. Stages and their version pickers include all historical artifacts; the old split between checkpoints and Earlier versions is removed. Original artifact IDs and #project/artifact/frame links remain supported. A video link may also carry time=<seconds>. Source notes render as readable text inside Project details; original files remain available. Download video and captions stay visible, with working files under More downloads. Storyboard scenes support an overview and an enlarged reader.

Project navigation fetches the current index before opening an exact link, including a version added after a tab opened. Returning tabs and a visible-page interval check for new project information. A paused project-level link can advance to newly delivered primary work; explicit selected versions, playback and drafts are preserved. New information disables stale approval controls until loaded. Unknown versions are explained without silently replacing the requested URL. New /project-assets/<project>/<opaque-file-id> URLs are stable when the index gains files; legacy numeric /project-files links remain supported. Assets are still confined to the same explicit project allowlist.

GET /feedback?project=<id> reads saved review feedback. POST /feedback adds one note, validates the exact artifact and context revision, and captures time or scene plus source paths. It uses explicit same-origin loopback requests, JSON/action headers/body limits, per-project confinement, the shared save lock, atomic writes, private before-images and idempotent request IDs. It writes only review-feedback.json and a private recovery journal. Source notes, index fingerprints, library data, approvals and media do not change. Unfinished save journals continue to block writes until recovered. Drafts retain version/moment during navigation; saved notes survive reloads and support optional copying. Ask the editing chat to apply them; see AGENTS.md/HANDOFF.md. Personal feedback is excluded from source releases with all other projects and runtime journals.

## Editable sources and sound — UX V20

A video artifact may register editor_source as an exact project-relative index.html. Known current checkpoints can resolve their single Editable project notes download’s adjacent index.html. History is never inferred from a shared folder or library preferred version. GET /project-tools is read-only; POST /open-editor requires exact project/artifact IDs and a current source revision. It copies confined source/media into projects/<slug>/work/studio-editor/<artifact>-<unique>/, launches the pinned local CLI without a shell, and returns a loopback editor URL. Original source and review exports are retained. A manual editor save does not update an export or approval; continue from the returned copy and render a new version through the recorded finishing process. This local-only folder is owner data and excluded from releases.

Sound reads a registered JSON Sound plan download, or sound-plan.json beside that exact editable source. Record title/artist, cues and a concise direction. Missing data stays unrecorded. Free/generated audio is the default; owner-library files are optional. Copy sound request names the exact review URL and does not fetch or generate audio.

Editor working copies are retained and reopened for the same project/artifact and unchanged original source revision. Manual changes in that copy are never replaced on reopen. A changed original source prepares a new copy and keeps earlier ones. The owner-only session pointer is in style-library/runtime/editor-sessions/; the full copy stays under its project. Generated render/history caches are not required to carry source into the new editor session.

## Final video promotion

Explicit final approval may promote a known older preferred video when its version/path match this project’s registered history. The selected current review remains the only approval target. Its saved cover and local media become the preferred source; duration is read from FFprobe when available (or registered metadata), never copied from a different cut. Earlier source/analysis is retained in a catalog entry with archived_from and source_sha256, hidden from the full-video browse grid. Exact technique example IDs stay the same and keep their previous version/path/hash/poster/range via that source snapshot. Saved technique borrowing notes keep their original source identity; current full-video notes use the new source revision. Preserve archived sources, removed_references and original media. Wrong project/version/path, stale snapshots or competing writes still block approval. This updates review/library metadata only, never an editor working copy or export.


## Feedback corrections and history

POST /feedback-note accepts edit/delete/restore with the note's optimistic revision and a unique request UUID. It preserves exact source coordinates, application state and prior snapshots in history; deletion sets deleted_at and is recoverable after reload from All saved notes. Applied notes remain visible on their original version, sorted by updated_at/created_at newest first, while copying includes only open, nondeleted notes. New immutable feedback links pin content revisions, so a stale copy cannot silently apply an edited instruction. No migration rewrites existing owner files.

Storyboard scene changes update media and scene notes in place, retain the filmstrip and overview/disclosure state, keep per-scene drafts, and replace the hash without scrolling the page to the review header. Stage and version changes retain their existing navigation behavior.

The scene strip belongs to the preview column, before scene details/feedback on narrow screens. Saved notes have an independently scrollable region, leaving the composer and note count visible. Keep each version’s note reading position; reveal newly saved/edited notes at the top. Automatically reveal a selected thumbnail horizontally on scene change, exact-link arrival and return from overview; never scroll the page to do so.
