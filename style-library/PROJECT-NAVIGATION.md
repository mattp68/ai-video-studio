# Project navigation and review contract

projects.json is an ignored local navigation index. Production STATUS/approval-state/brief/storyboard/review notes remain authoritative. Empty installs create projects.json from projects.example.json. Changing note hashes flags stale navigation; read and reconcile decisions before refreshing.

A project record includes id, title, subtitle, format (video/presentation/carousel), state (in_progress/review/approved/final), stage, summary, next_step, primary_artifact, source_notes and artifacts. Optional cover_path and reference_id point to real saved assets. Each source note has project-relative path, label and SHA-256. Artifacts have stable id, label, type (video/board/carousel/document), version and role (current/assembly/storyboard/baseline/final/history). Video/document has path; board/carousel has frames with path/title/notes; downloads have path/label. URLs and availability are derived by the server, not stored. See scripts/smoke.py for a complete synthetic example.

Use scripts/register.py project <studio-entry.json> after reading/updating source notes. New registration cannot claim final approval. Replacing a record with an existing saved decision requires explicit reconciliation, preserving its approval-state.json/history. Unknown files/absolute paths/unsupported types/symlink escapes are unavailable. /project-files/<id>/<numeric-slot> serves only the exact registered project's allowlist.

Before a final review, register a matching pending library entry or prepare reference_entry plus reference_poster_source in the project descriptor. reference_entry uses the library shape (title, subtitle, creator/creator_id, summary, tags, palette, traits, keep, avoid, moments, notes, version, collection, evidence and media_path for video; slides for carousel; project_id/asset_type project for slide assets). The poster must be an actual saved image in this project. It is copied into a new versioned library poster only when the user marks final. Keep entry/version/media and any linked technique source hash/windows synchronized. Do not approve your own production output.

Review controls affect only the current primary checkpoint. Approve spoken cut advances to storyboard; Approve storyboard advances to edit; Approve & mark final promotes exact media/library metadata; Reopen requests changes and retains accepted assets. Historical checkpoints have no approval control. Events include UUID/date/version/files/hashes. STATUS receives a current-decision block, review notes append, legacy active-edit fields update when present and index note fingerprints refresh. Final does not publish.

Writes use exact Origin/Host/header/JSON guards, revision checks and per-file atomic replacement with private transaction backups. An unfinished prepared transaction blocks further writes. Inspect its named style-library/runtime/review-actions/<UUID>/transaction.json, confirm the before-images and current files, then `python3 style-library/review_actions.py recover <UUID>`. Recovery refuses to overwrite later edits. Do not delete journals to bypass a failed save. They and all actual owner registries/decisions are excluded from the release export.
